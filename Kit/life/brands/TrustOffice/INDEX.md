## 🔴 Deployment Protocol (Railway) — MANDATORY

> **Before ANY Railway deployment, code push to a Railway-connected repo, or Railway operation:**

1. **Load the `railway-deploy` skill** via MCP: `mcp_skill_registry_load_skill('railway-deploy')`. Do NOT freestyle deployments.
2. **Spawn a dedicated deployment subagent** via `delegate_task` with the railway-deploy skill loaded in its context.
3. **Include the deploy gate context** in every deployment subagent: `bash ~/.openclaw/workspace/SYSTEM/scripts/deploy-gate-context.sh <brand> <project> <service>`
4. **Run the deploy pre-flight gate**: `bash ~/.openclaw/workspace/SYSTEM/scripts/deploy-preflight.sh <brand> <project> --subagent`
5. **The Railway CLI is permanently disabled.** NEVER use `railway up`, `railway init`, `railway link`. Use `rwy` CLI or GraphQL only.
6. **Verify after deploy**: `rwy deployments <project>/<service> --n 1` must show `status == SUCCESS`. Run health check on live URL.
7. **Do NOT report "deployed" without verification.** Jeff has corrected this multiple times.

**Anti-pattern:** Deploying without loading the skill → failed deployments, wrong methods, Jeff corrections.
**Correct pattern:** Load skill → spawn dev subagent → preflight gate → deploy → verify → smoke test → report.
